Fix 2 critical bugs: missing urllib.parse import, wrong rate-limit endpoint keys

Bug 1: scan_repo_endpoint used urllib.parse.urlparse() to validate raw_url hostnames, but urllib.parse was never imported anywhere in the file - this caused a guaranteed NameError on every single file scanned by /scan-repo, since the check runs inside the per-file loop. Fixed by adding "import urllib.parse" near the other stdlib imports at the top of the file.

Bug 2: _ENDPOINT_SPECIFIC_LIMITS used the keys "/login" and "/register" for the login and registration brute-force rate limits, but the actual routes are "/auth/login" and "/auth/register" - meaning _check_endpoint_specific_limit's dictionary lookup never matched the real request path, so the 5-attempts-per-5-minutes login rate limit and 3-attempts-per-5-minutes registration rate limit never applied at all. This is separate from and in addition to login_user's own internal progressive-lockout mechanism (fixed earlier this session), which does still work independently - but this endpoint-level rate limit was silently non-functional the entire time. Fixed by correcting both dictionary keys to match the real route paths.

Verified both fixes directly: urllib.parse.urlparse() now correctly parses a URL and returns the expected hostname with no error. A test sending 7 consecutive attempts to /auth/login's rate limiter (limit is 5) now correctly returns True for the first 5 and False for the last 2, confirming the limit is genuinely enforced against the real route. Full 23-test regression suite passes with zero failures.
